Executive summary

    Experimental protocol

    ItemSetting
    ModelClaude Sonnet 5, invoked through the Claude Code CLI in print mode; resolved model identifier recorded for every call (claude-sonnet-5)
    Invocation controlsFixed task-specific system prompt; all built-in tools and MCP servers disabled; empty working directory; decoding parameters are not user-controllable through the CLI
    Evaluation modeContracts 1 to 5: oracle mode, used only to seed the feedback memory. Contracts 6 to 50: non-oracle mode, in which no ground-truth information influences feedback, attempt selection or stopping
    Framework parametersmax_attempts=3, threshold=0.7, early_stop=block, topk_candidates=40, condense_window=5, block_eval=dilated, block_dilation=1, line_tolerance=0, smart_feedback=llm
    GPT-4o referencePredictions from the October 2025 GPT-4o run (oracle mode), re-scored on the same 45 contracts against the corrected annotations
    Tool baselinesOyente, Securify, Mythril, SmartCheck, Manticore and Slither false negatives recounted on the same 45 contracts from the published SolidiFI tool reports (Ghaleb and Pattabiraman, ISSTA 2020)
    MetricsMacro averages over contracts. Line level requires the exact annotated line; block level credits a prediction within the annotated span (one-line dilation). Per-bug false negatives count an injected bug as missed when none of its annotated lines is predicted, which matches how the tools are scored

    Threats to validity

    • Different evaluation modes. Sonnet 5 is evaluated without the oracle; GPT-4o figures come from an oracle-mode run. This comparison favours GPT-4o, so Sonnet 5's advantages are conservative, but model and mode are not separated.
    • Model access. The CLI does not expose temperature or other decoding parameters, and no model snapshot beyond the resolved identifier can be pinned.
    • Single execution. Each contract was run once. Agreement between attempts within a contract is reported below as partial evidence of stability; it is not a measure of run-to-run variance.
    • Annotation corrections. Four Re-entrancy annotation files were corrected before these runs (two missing header fields, one missing line value, one out-of-range line). GPT-4o was re-scored against the same corrected files.
    • Baseline recount. The recount of tool false negatives reproduces 17 of 26 published SolidiFI totals exactly and the remainder within 2.7%.
    • Duplicate annotations.
