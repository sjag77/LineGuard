Project

Date
13 September 2026
Scope
Re-entrancy category, contracts buggy_1 to buggy_27 in pipeline order (20 contracts)
Purpose
Functional check of the revised pipeline with a second model backbone, and an indicative comparison with the recorded GPT-4o run

Executive summary

The revised LineGuard pipeline ran end to end with Claude Sonnet 5 on 20 Re-entrancy contracts and was compared contract by contract with the recorded GPT-4o results on the same 20 contracts. Both runs used the oracle evaluation configuration and the same framework parameters. The outcome differs sharply by granularity:

  • Block level. Sonnet 5 achieved a higher block F1 on all 20 contracts (macro 0.434 to 0.586). The gain comes from recall (0.288 to 0.430); block precision was essentially unchanged (0.967 to 0.943).
  • Line level. Line F1 was effectively the same (0.626 to 0.620; 8 contracts better, 10 worse, 2 tied; sign test p = 0.81). The two models reached it differently: Sonnet 5 recovered more vulnerable lines (recall +0.155, p = 0.013) but also flagged more non-vulnerable lines (precision −0.190, p = 0.031).
  • Refinement effort. Sonnet 5 needed more feedback rounds: an average of 2.75 attempts per contract against 2.30 for GPT-4o, with 15 of 20 contracts using all three attempts.

In short, on this sample Sonnet 5 is the broader detector rather than the more accurate one. Because the model and the invocation method changed together, and the sample is small, these results are indicative only and should not be reported in the manuscript.

Threats to validity

  • Two factors changed at once. Sonnet 5 was called through the Claude Code CLI, which applies its own system prompt and does not expose decoding parameters or a pinned model snapshot. GPT-4o was called directly through its API. Differences cannot be attributed to the model alone.
  • Small sample. 20 of the 50 Re-entrancy contracts. These 20 are harder than the category average: GPT-4o's line F1 is 0.626 on them against 0.690 on all 50.
  • Single execution. Run-to-run variance was not measured for either model.
  • Oracle configuration. Attempt selection and feedback consulted the ground truth in both runs, so absolute scores are upper bounds.
  • Missing line annotations. Contracts buggy_17 and buggy_21 have no point-level line annotations, so both models score 0 at line level on them. Excluding the two, line F1 is 0.696 (GPT-4o) and 0.689 (Sonnet 5); the conclusion is unchanged.
  • No token or cost data. The CLI does not report token usage, so cost cannot be compared.

Conclusion

The revised pipeline works with a second model backbone without modification. On these 20 Re-entrancy contracts, Claude Sonnet 5 recovers more of each vulnerable block and more vulnerable lines than GPT-4o, at the cost of lower line-level precision, and ends up with the same line-level F1. The block-level advantage is consistent across every contract, while the line-level result is a trade-off rather than an improvement.

A comparison suitable for the manuscript would need both models called through their APIs with pinned model identifiers and fixed decoding parameters, the full set of 50 contracts, and repeated runs to estimate variance.
